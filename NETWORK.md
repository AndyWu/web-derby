# Local multiplayer and offline setup

The host creates one invitation per guest. The guest scans or pastes it, creates an answer, and the host scans or pastes that answer. Wait for connected status before inviting the next guest. A room has one host and up to five guests. All devices need to be on a network that permits device-to-device traffic.

Invitations contain compressed, complete WebRTC SDP and gathered host ICE candidates. They are not guaranteed to fit into a tiny QR; retain a selectable text field and copy/paste fallback. An invitation is single-use. No STUN, TURN, cloud signaling, or Internet relay is used. Traffic is encrypted by WebRTC; the room host remains authoritative for gameplay. Inputs and snapshots use binary Float32Array payloads over unordered data channels with maxRetransmits: 0. The public API accepts arrays and delivers arrays. Input packets require a finite steering value in [-1, 1] plus five binary control flags. Snapshots require tag 88 followed by up to six groups of four finite car values. JSON [77, slot] is accepted for the host slot control message; repeat this control because the transport can drop packets.

An isolated LAN can still fail: guest Wi-Fi client isolation, firewalls, browser mDNS host-candidate handling, and OS restrictions can prevent direct WebRTC connectivity. Two-way QR exchange cannot remove those restrictions. Test the actual devices and router before travel. An iPad hotspot without an active cellular plan/SIM is not guaranteed to be available; a travel router or another known-working local network is safer. This project does not provision a hotspot.

Install and open the production app over HTTPS while online on every device before travel, then reload once so the service worker controls the page. The build script `scripts/cache.mjs` stamps the service worker with a content-derived build ID and writes both `dist/cache-manifest.<build-id>.json` and `dist/cache-manifest.json` as `{ "version": "unique-build-id", "assets": ["/", "/index.html", "/manifest.json", "/icon.svg", "/assets/all-built-assets..."] }`. Include every emitted asset. The service worker installs atomically only when every listed asset downloads. Confirm a cold reopen in airplane mode before relying on offline use. Development mode is not the offline distribution. Camera scanning and Web Crypto require a secure context; localhost is suitable for development on that device only.

`FamilyNetwork` exports `hostOffer()`, `joinOffer(payload)`, and `acceptAnswer(payload)`, all asynchronous. Offer and answer methods return strings for QR rendering with `qrcode`; use `jsqr` to decode camera frames where native BarcodeDetector is absent. Set `onInput(array, peerId)` on a host, `onSnapshot(array, peerId)` on a guest, and `onStatus(status, peerId)` for UI. `peers` is a Map, `connectedCount` counts open guest channels, `sendInput(array)` sends guest controls and `broadcast(array)` sends host state. `close()` leaves the room.

`createFamilyPass(seats)` and `verifyFamilyPass(pass)` demonstrate offline signed seat metadata. The pass is self-issued and includes its own verification key. Anyone can issue one; it is **not purchase verification, DRM, or a payment entitlement**. A production paid family license requires an externally issued signature checked against a trusted embedded public key, plus an explicit policy for offline seat accounting. This prototype enforces the six-device room cap locally, not globally across disconnected rooms.

`persistFamilyPass(pass, profiles)` verifies and stores the demo pass and up to six named local profiles in IndexedDB. Profiles can be names or objects with a name field. `loadFamilyPass()` re-verifies stored data and returns `{pass, profiles, claims}`, or null if absent/invalid. Storage failures reject and should be reported to the user. This local storage is not a trusted purchase ledger.
